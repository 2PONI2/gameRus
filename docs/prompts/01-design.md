# Промт 1. Дизайн-документ и архитектура

Результат сохранить в `docs/design/`.

```
Этап 1. Пока без кода игры - только проектирование.

Составь краткий, но конкретный дизайн-документ и архитектуру.

1. Концепция: название игры (3 варианта), сеттинг (например, русская деревня/посёлок, где жители вместе поднимают общее дело), 4 игровых персонажа (разные, дружелюбные, без стереотипов), 1-2 NPC (например, бабушка-заказчица, председатель).
2. Игровой цикл: заказы появляются в очереди с таймером (как в Overcooked), выполнение даёт очки и бонус за серию, провал снижает счёт. Итог уровня 1-3 звезды. Опиши формулу очков.
3. Механики: перемещение, подобрать/положить/передать другому игроку, удержание кнопки для работы на станции, бросок предмета, рывок. Станции: источник ресурсов, обрабатывающая станция (с прогресс-баром), стол/склад, сборочная станция, окно сдачи заказа, урна. Механика взаимопомощи: часть задач физически невозможно выполнить в одиночку (тяжёлое брёвно несут вдвоём, один держит лестницу - другой красит и т.п.).
4. Уровни (минимум 6):
   - Уровни 1-4: каждая локация посвящена одному делу (например: 1 - субботник во дворе и посадка сада; 2 - строим сруб; 3 - помогаем бабушке с хозяйством и ремонтом; 4 - ремонт сельского клуба). У каждой своя уникальная механика-препятствие (река с мостом, дождь, движущаяся платформа и т.п.).
   - Уровень 5-6: "Большой день" - все ремёсла на одной карте, заказы смешанные, ценность - всё вместе.
   - Для каждого уровня: цель, станции, типы заказов, препятствие, длительность, пороги звёзд, минимальное число игроков, масштабирование под 2/3/4 игроков.
5. Данные: как описывать ресурсы, рецепты (цепочки преобразований), заказы, уровни через ScriptableObject так, чтобы новый уровень добавлялся без правки кода.
6. Архитектура проекта: структура папок, список сборок (asmdef), классы и их ответственность, схема сетевой синхронизации (что синхронизируем через NetworkVariable/RPC, что считаем только на хосте), как один код работает локально и по сети, как устроен спавн локальных игроков на разных устройствах ввода.
7. Список рисков и как их снимаем (рассинхрон предметов при передаче, задержка ввода, NAT).
8. План разработки по этапам 2-7 с критерием готовности каждого.

Выведи в виде структурированного документа. Жди моего одобрения перед этапом 2.
```
